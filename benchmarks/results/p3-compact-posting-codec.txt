BIFROST — P3: COMPACT POSTING CODEC

Hardware: Apple MacBook Air M2
Architecture: Darwin arm64
Benchmark: BenchmarkSaveIndex
Iterations: 3
Database: bbolt

OBJECTIVE
---------

Replace Gob-based posting serialization with a compact binary codec
using unsigned varints, delta-encoded document IDs, and delta-encoded
token positions.

Numeric document IDs are used in persisted posting lists to reduce
storage overhead.

  Before: 11,015,026 allocs/op
  After:  12,409,495 allocs/op
  Increase: 12.7%


IMPLEMENTATION
--------------

- Added internal/codec package.
- Implemented compact posting-list encoding and decoding.
- Used unsigned variable-length integer encoding.
- Delta-encoded numeric document IDs and token positions.
- Added the BCP1 format marker.
- Introduced numeric document ID mappings.
- Bumped storage schema version to 2.
- Added round-trip, invalid-input, malformed-data, corruption,
  and document-mapping tests.
- Added fuzz testing for the decoder.

CONCLUSION
----------

The compact posting codec reduced the database size by approximately
42.4% and index-save time by approximately 35.6% on the 100,000-document
benchmark.

Allocated bytes decreased by approximately 59.2%, although the number
of allocations increased by approximately 12.7%.

These are local benchmark results and may vary with hardware, Go version,
and workload.
